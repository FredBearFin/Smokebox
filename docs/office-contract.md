# Back office (the hidden world): integration contract

Three agents build it in parallel. **Office A** owns the frame and the shared kit (`80-office-core.js`, `30-office.css`) and the pages Pace, Tickets, Stations (`81-office-pace.js`). **Office B** owns the pages Sales and money, Safety, Stock and 86 (`82-office-money.js`, `83-office-safety.js`, `85-office-stock.js`, `31-office-money.css`). **Office C** owns Menu and settings (`84-office-data.js`, `32-office-data.css`). Everyone codes against THIS file. A ships `SB.office.kit` early (first thing, within about 20 minutes) and keeps its signatures stable; B and C start with reading, planning, the metrics calls and chart specs, and plug into the kit as soon as `src/js/80-office-core.js` contains `SB.office.kit`. Until then, write against the signatures below.

The shell already provides the office layer, the ignition, the PIN gate, `SB.router` (`#/office/<id>`), the theme tokens (`--o-*`, remapped onto the floor token names inside `.office`, so `.btn .chip .field .stepper .seg .toggle .panel` all work) and calls `SB.office.mount(el, section)`, `SB.office.navigate(section)`, `SB.office.unmount()`. **The office is mounted at every ignition and unmounted after every close**: every timer, subscription and chart must be cleaned up in `destroy`.

Each page file registers itself: `SB.office.registerPage(id, {title, icon, order, render(container, ctx) -> {update?(), destroy?()}})`. `render` is called each time the page is shown. If a page throws while rendering, the frame shows an inline error card with the page name (never a blank screen) and the other pages keep working.

## 2. `ctx` (passed to `render`)

```
ctx.filters         { range:{id,from,to,label}, channel:'all'|channelId, source:'all'|'live' }   (live view of the current filter state)
ctx.dataset()       -> SB.store.dataset({sample: filters.source==='all' && SB.sim && SB.sim.sampleEnabled()})   (memoised by the store)
ctx.opts()          -> {from, to, channel, now}                      what to hand to SB.metrics
ctx.prepared()      -> SB.metrics.prepare(ctx.dataset(), ctx.opts())  ONE handle per refresh: pass it to every metric call
ctx.now()           -> SB.store.now()
ctx.metrics         SB.metrics
ctx.onFilterChange(fn) -> off         fires after any filter change or data refresh with (ctx)
ctx.navigate(id)    go to another page                 ctx.openSheet(name)  SB.sheets.open
ctx.theme()         'ember' | 'paper'                  ctx.kit  SB.office.kit
```
Filters (sticky bar, owned by A): range Today / Yesterday / Last 7 days / Last 14 days / Custom (two date inputs), channel (All + the 4 channels), source (Live only / Live + sample). Defaults: `last14` and `all` when sample history exists and is enabled, else `today` and `live`. The bar is not shown on the Data page's own forms but the data banner is. The data banner (one line, always visible): "14 sample days plus 23 live tickets. Sample data is generated by the simulator." (counts from `dataset().counts`, honest when sample is off or missing).

## 3. `SB.office.kit` (A implements; everyone uses; all return plain objects with `el`)

The kit makes pages declarative: you describe cards; the kit builds them, wires "View as table", refreshes them when filters or data change (the office refreshes at most every 3 s while open and immediately on filter change), and destroys everything with the page.

```
const page = kit.page(container, ctx, {id})    // builds: headline slot, tile row slot, body grid (12 columns, collapses to 1 column under 900 px)
page.headline()                                // one plain sentence: SB.metrics.headline(id, p, opts); updates on refresh
page.tiles([{id, label?, kpi?:'medianMs'|..., value?:(p,ctx)=>..., unit?, spark?:(p,ctx)=>number[], format?}])
                                               // KPI tiles: value, unit, change vs previous equal period as arrow + word (not colour alone), sparkline.
                                               // With kpi, the kit reads SB.metrics.compare(...).kpis[kpi] and .spark[kpi]; with value(), you supply it.
page.section(title, sub?)                      // heading that spans the full grid width
page.card({type, title, sub?, caption, span=6, height=260, table=true, spec:(p,ctx)=>chartSpec, onSelect?, actions?:[{label,icon,onClick}], empty?})
                                               // chart card: SB.charts[type](body, spec(p,ctx)); "What to look for: ..." caption under the title; a View as table toggle (chart.setTable);
                                               // `empty` text when spec returns null or the chart reports no data. span 3|4|6|8|12.
page.panel({title, sub?, caption?, span=6, render:(body, p, ctx)=>({update?(p,ctx), destroy?()})})   // arbitrary content in the same card chrome (tables, forms, lists)
page.table({title, sub?, caption?, span=12, columns:[{key,label,align?,format?,sort?:true,width?}], rows:(p,ctx)=>[...], onRow?(row), empty?, pageSize?:10})
                                               // sortable, keyboard-operable table (real <table>), numbers right-aligned and tabular
page.insights({limit=8})                       // SB.metrics.insights cards: tone icon (good/info/warn/bad: icon + word + colour), title, body
page.refresh()                                 // force refresh now        page.destroy()
kit.empty({title, body, action?:{label,onClick}}) -> {el}      kit.errorCard({title, body, details?}) -> {el}
kit.fmt  = {ms, sec, pct, money, g, num, hour, clock, date}    thin wrappers on SB.util (ms -> '4m 30s'; pct takes a FRACTION 0..1; money '$12.40'; g -> '3.2 kg' from 1000)
kit.chip / kit.button         use SB.ui.chip / the .btn classes
```
`spec(p, ctx)` returns an `SB.charts` spec (see SPEC 20 and `SB.charts` header). Return `null` to show the card's `empty` message. A chart must say what it shows in `ariaLabel`. Cards sit on `background: var(--ch-surface)` (`.ch-card` does it); hero numbers use `.ch-big-h`.

## 4. Look and feel (all office pages)

* Ember (default dark) and Paper (light) via `SB.theme.office()/setOffice()`; both must look finished. Thin lines, generous space, one accent. Left rail with icon + word (collapses to a bottom tab bar under 720 px), page title row with "Back to the line" (`[data-back-to-line]`), theme toggle.
* Every page opens with the plain-language headline sentence, then KPI tiles, then charts. Every chart card has a one-sentence "what to look for". Every chart can be viewed as a table. Every KPI shows value, unit, the change against the previous equal period (arrow + word) and a sparkline when there is a series.
* Honesty: whenever sample data is in the range, the banner says so; empty or thin data says "Not enough data yet" and shows what would fill it; never a chart of zeros for unknown values (metrics return `null` for unknown; skip it).
* Performance: a page render with the full 14-day sample must feel instant (< 150 ms for the metric calls through one `prepare` handle, charts < 100 ms each). Never recompute inside a chart callback; the kit refreshes cards in one pass.
* Accessibility: landmarks (`nav`, `main`), `aria-current="page"` on the rail, keyboard: `[` and `]` previous/next page, `Esc` leaves the office (the shell handles Esc and Back), focus moves to the page title on navigation, charts keep the keyboard behaviour built into `SB.charts`.
* Units: grams and kilograms only (`kit.fmt.g`). Times of day in 12-hour form with am/pm (`SB.util.fmtHour`). Dates short ("Fri 10/16").
